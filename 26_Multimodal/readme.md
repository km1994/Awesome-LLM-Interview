## 一、多模态的基本盘

### 1.1 多模态模型和纯文本 LLM，架构上差在哪？

差在输入侧，主干几乎没动。

LLM 的输入是 Tokenizer 切出来的离散 token，天生就落在模型的嵌入空间里；图像、音频、视频是连续信号，得先过编码器变成向量序列，再用映射器投影到 LLM 的嵌入维度。所以多模态的架构等于「模态编码器 + 映射器 + 一个基本不动的 LLM」。

难点不在"接上去"，而在让投影后的视觉向量落进 LLM 已经理解的语义邻域。这就是模态鸿沟。

### 1.2 多模态的数据工作难在哪？

难在"有数据"和"数据能用"是两件事。

图文对天然存在于网页里，`<img>` 旁边的 alt 文本、正文、标题都算，获取成本很低，但噪声极大，图不对文、正文与图无关都是常态。所以预训练的关键工序不是找数据，是洗数据：先用 CLIP 分数粗过滤，再让 Captioner 重新生成描述、Filter 判真伪，BLIP 的 CapFilt 就是这套。

到了指令微调阶段，高质量多模态指令数据几乎没有现成来源，LLaVA 干脆用纯文本 GPT-4 合成，等于拿语言先验去补视觉标注的缺口。

### 1.3 多模态模型的短板在哪？

有三类问题到现在都没真正解决。

一是细粒度空间关系，问"左边的猫还是右边的猫"，CLIP 系基本靠猜，因为对比学习只对齐全局语义，不约束位置。二是计数和密集小目标，视觉 token 一池化，小物体信息就被平均掉了。三是纯视觉逻辑，比如从两张图的细微差异推结论，模型容易退化成先描述再瞎推。

根子都一样：视觉信息进 LLM 之前被有损压缩了。

### 1.4 多模态的嵌入和传统词嵌入不是一回事？

不是。传统词嵌入只在语言内部定义"相近"，回答的是"两个词是不是常出现在相似上下文"。

多模态嵌入要求跨模态可比：同一语义的图像向量和文本向量要靠近，不同语义的要拉开。它得同时满足语义对齐和空间统一这两条。而且对齐是多对多的，一张图可以对应"一只狗"，也可以对应"一只金毛在草地上"，所以训练目标通常是批次内的软匹配，不是一对一回归。

### 1.5 模态鸿沟是什么？

指不同模态的嵌入在共享空间里并不真正重合，各自形成互不相交的锥形簇。

成因在训练目标。对比学习只给相对距离的监督，它要求图片和它的文本比别的文本更近，却从不要求两者绝对重合，那么最省力的解就是各模态各自成簇、只在簇间维持相对次序。

带来的现象很具体：跨模态检索的绝对相似度没有可比性，图-图相似度天然高于图-文相似度；零样本分类的阈值没法迁移；视觉指令微调之后模型还是倾向忽略图像、只看文本。想缓解得加更强的跨模态监督，比如 ITM、生成式重建、token 级对齐，光靠放大 batch 没用。

### 1.6 多模态任务怎么分类？

按输入输出的模态组合分最实用，四类。

跨模态检索是文找图或图找文，输出是排序结果；视觉理解生成是图到文，VQA、图像描述、文档问答都在里面；条件生成是文或图到图或视频，输出是像素；多模态交互是图加语音加文本到任意模态，实时语音视频助手和 GUI Agent 属于这类。

分类的意义在于技术栈完全不同：前两类靠编码器加映射器加 LLM 就够，第三类必须引入生成器，第四类还得额外做流式与时延工程。

### 1.7 预训练阶段在做什么？

目标是把视觉表示拉进语言模型能理解的空间。

常用任务有三类：对比学习让图片和文本互相拉近拉远，图文匹配做二分类判断配不配，语言建模看图生成描述。工程上一般分两段走，先只训映射器、编码器和 LLM 都冻住，让视觉向量先落到 LLM 的语义邻域，再解冻连接部分做联合微调。

冻结顺序之所以重要，是因为 LLM 里已经压着海量语言知识，早期就让视觉梯度冲进去会把语言能力冲坏。

### 1.8 微调阶段在做什么？

目标是从"会描述"变成"会对话"。

做法是把「图像、指令、回答」三元组喂进去做监督微调，数据规模通常比预训练小两三个数量级。参数效率上普遍用 LoRA，或者只训映射器加 LLM 的部分层。

这两年还会在 SFT 之后接一轮 DPO 或带可验证奖励的 RL，用来压幻觉、提升推理链质量。

### 1.9 预训练和微调怎么分工？

预训练买通用性，微调买任务能力，两边都有代价。

预训练数据量大、覆盖广，模型能应付没见过的新任务，但算力成本最高，而且容易冲坏语言能力，视觉梯度占主导时文本困惑度会上升。微调便宜，几十到几百 GPU 小时就够，但容易过拟合到任务模板，通用性反而下降。

我一般会这么配：冻住 LLM 只训映射器做对齐，再用小学习率解冻部分层，同时在混合数据里保留一定比例的纯文本语料。最后这一条是防止语言能力退化最有效的一招。

### 1.10 四类任务的技术栈有什么不一样？

检索类的难点在召回排序和索引规模，架构最轻，双塔模型就够，根本不需要 LLM。

理解生成类的难点在幻觉和细粒度定位，这是当前 MLLM 的主战场。条件生成类的难点在可控性和一致性，需要扩散或流匹配生成器，跟理解类模型是两套东西。交互类的难点在端到端时延和可打断，工程复杂度最高，通常要级联或全双工流式架构。

## 二、编码器

### 2.1 为什么不直接用 LLM 处理图片？

因为 LLM 的输入空间只接受嵌入向量。

图片是像素矩阵，音频是波形，视频是帧序列，这些都没法直接吃进去。理论上可以走两条路：一是把原始信号直接切 patch 塞进去，这是原生多模态的做法；二是先用专门的编码器压成语义表示，这是模块化路线。

原生更彻底，模块化更省算力还能复用已有的视觉预训练成果，所以现在工业界主流还是后者。

### 2.2 视觉、文本、音频三条前端链路分别怎么走？

共同点是都要先把连续信号离散化，再用 Transformer 建模长距离依赖。差异全在前置预处理。

视觉那边把图像切成 16×16 的 patch，线性投影成 token，视频还要多加一步帧采样再把多帧 token 拼起来。文本最简单，Tokenizer 分词直接进 Transformer，而且多模态里通常直接复用 LLM 自己的文本能力，不单独建编码器。音频的关键一步是把波形转成梅尔频谱图，这样它就变成了一张二维图像，可以复用视觉编码器的思路。

### 2.3 编码器输出的向量能直接喂给 LLM 吗？

不能，卡在两个层次上。

第一层是维度不匹配，视觉编码器输出 1024 维、LLM 嵌入 4096 维，一层线性层就能解决。第二层才是真问题：语义空间不匹配。视觉编码器是在图像-图像或图像-文本对比目标下训出来的，它的向量分布和 LLM 的文本嵌入分布毫无关系，直接投影过去 LLM 看到的是乱码。

所以映射器不是升维工具，它要把视觉特征重新组织成 LLM 能认的"类词向量"，而且这个过程必须用图文数据训出来。

### 2.4 ViT 是怎么工作的？

四步：图像切成固定大小的 patch，每个 patch 拉平后线性投影成 patch embedding，加上位置编码，前面拼一个可学习的 `[CLS]`，整体送进标准 Transformer 编码器，最后拿 `[CLS]` 的输出做分类。

它的取舍在于放弃了 CNN 的局部性和平移不变性这两个归纳偏置。好处是全局注意力让模型能直接建模任意两个 patch 的关系，架构统一；代价是必须靠海量数据把偏置学回来。ViT 在小数据集上打不过 ResNet，只有到了 JFT-300M 那个量级才反超。

这条结论对做多模态的人挺重要：视觉编码器基本都得用大规模预训练权重初始化，不能从零训。

### 2.5 ViT 早期为什么一定要有监督预训练？

因为没有别的办法拿到足够规模的标注。

逐图人工标注成本高、规模上限明显，ViT 当年用 JFT-300M 这种内部数据集正是这个原因。而且一张图只有一个类别标签，信息量太低，模型学到的表示只够区分几千个类，对位置、纹理、物体关系的刻画很弱，而下游检测分割恰恰需要这些。

后来两条替代路线出现了：MAE 走自监督重建，不需要标签；CLIP 走图文对比，用现成的弱标注。

### 2.6 MAE 的遮蔽率为什么能到 75%？

因为它只把可见的 25% patch 送进编码器，再用一个轻量解码器重建被遮住的像素，而且这个遮蔽率恰恰是它有效的关键。

图像的信息冗余远高于语言，被遮掉的 patch 大部分能从邻域猜出大概，所以任务仍然可学，但难度又足够。75% 不是拍脑袋，论文里做过消融，遮蔽率太低会退化成"抄邻居"的简单任务，学不到好表示。

效率的来源是非对称编解码：编码器只处理 25% 的 patch，训练提速约三倍，而沉重的解码器只在预训练时用，下游直接扔掉。

### 2.7 主流多模态模型为什么都用 CLIP 系当视觉塔？

因为接 LLM 的时候，编码器的语义对齐度比视觉表征质量更重要。

CLIP 经过图文对比预训练，输出向量本身就带语义，而且和语言空间有粗略对齐，映射起来容易得多。MAE 的表示质量其实很好，但它是纯视觉目标训出来的，跟语言空间没关系，接 LLM 反而更费劲。

MAE 的主战场是纯视觉任务，检测、分割、医学影像，优势是不依赖图文对，可以吃任意规模的图像数据。

### 2.8 Whisper 编码器是什么结构？

输入是 80 维梅尔频谱图，按 30 秒窗口切段，编码器是一层卷积加 Transformer，解码器是自回归文本生成器。

它真正的贡献不是架构，而是弱监督数据规模，68 万小时带噪网络音频，不做精细清洗，靠数据量盖过标注质量。训练目标是多任务的序列到序列：转写、翻译、语种识别、时间戳预测共用一套解码器，用特殊 token 切任务。

这套设计让它对噪声口音很鲁棒，也让它成了一个很好用的通用音频特征提取器，很多语音大模型直接把它的编码器拿来当前端。

### 2.9 语音 Tokenizer 和 Whisper 编码器有什么区别？

输出形式不同。Whisper 编码器给连续特征向量，语音 Tokenizer 给离散的码本索引。

实现上通常用残差向量量化，第一层量化器编码主要信息，后续层逐级编码残差，多个码本叠加逼近原始声学特征，代表有 EnCodec、SoundStream、Mimi、SpeechTokenizer。

用途差别很大。连续特征适合做理解，因为它保留了声学细节；离散 token 适合做生成，因为它可以被自回归 LLM 直接预测。等于把语音变成一种"外语词的序列"，同一个 LLM 就能既说文本又"说"语音。所以选型看任务，要理解用编码器，要生成用 Tokenizer。

### 2.10 高分辨率图像进 ViT 会出什么问题？

token 数按边长平方涨。`(H/16) × (W/16)`，边长翻倍 token 就翻四倍，注意力计算量还要再平方一次，显存和时延都受不了。

但文档 OCR、界面理解、密集小目标又必须要高分辨率。常见解法有四类：动态分块，先把大图切成固定尺寸子图分别编码再拼 token，简单有效但切分会割断跨块语义；多尺度编码，同时用低分辨率全局图和高分辨率局部块；token 压缩，编码后把相邻视觉 token 合并；窗口注意力，把 ViT 内部的全局注意力换成局部窗口。

工程上一般是动态分块加 token 压缩的组合。

### 2.11 原生动态分辨率解决的是什么？

解决"必须缩放到固定尺寸"带来的表示损失。

固定 336×336 意味着所有图都得缩放，长图被压扁、宽图被裁掉、小图被拉伸到模糊，形变本身就在丢信息，而且模型永远见不到原图的像素密度。原生动态分辨率保留原始宽高比和像素密度，按实际尺寸切 patch，token 数随内容自适应，文档图自然拿到更多 token。

难点在位置编码得从一维改到二维甚至三维，因为 token 网格不再固定，这也是 Qwen2-VL 要用 M-RoPE 处理时间、高、宽三分量的原因。代价是样本间序列长度差异大，批处理、显存峰值和推理调度都要重新考虑。

### 2.12 减 token 和减计算量是一回事吗？

不是，两者作用在不同环节。

token 压缩作用在编码器之后，目标是减少送进 LLM 的 token 数，直接降低 LLM 的注意力开销和 KV Cache 占用，收益最直接，代价是可能把密集小目标的信息平均掉。稀疏或窗口注意力作用在编码器内部，把注意力从 O(n²) 降到接近线性，缓解的是编码阶段本身的算力压力，但最终 token 数一点没少。

两者不冲突，可以叠加：先让编码器用窗口注意力扛住高分辨率，再压缩输出 token 让 LLM 轻装上阵。实际取舍时优先做压缩，因为它同时省显存和时延。

### 2.13 视觉 token 该留多少个？

这问题没有标准答案，因为它取决于图像的信息密度，而固定压缩率恰恰假设了所有图的密度一样。

实际上文档表格要几百上千 token，"这张图里有什么"几十个就够。固定压缩两头都亏：按简单图设上限，文档图会丢字；按文档图设上限，朋友圈图片白吃几倍算力。

所以现在走内容自适应，先用一个轻量打分器或路由模块判断复杂度，再决定压缩率。落地时有个省事的做法：先按"文档型还是自然图型"做二分类路由，就能拿到大部分收益，不必一上来就上可学习路由。

### 2.14 编码器到底该不该冻结？

看图文数据规模和视觉分布是否领域内。

冻结有三个好处：省显存、训练稳、语言能力不容易被冲坏。数据量小（百万级）或者视觉分布跟编码器预训练分布接近时，冻结是首选，LLaVA 早期和 BLIP-2 都是冻结路线。

需要解冻的情况有两种。一是领域偏移明显，医学、遥感、工业质检这些分布编码器没见过，不解冻它输出的特征就是错的；二是数据量足够大，千万级以上时联合训练收益明显。实务上折中是渐进解冻加编码器用小学习率，训练后期再解冻，避免一上来就破坏视觉表示。

## 三、映射器

### 3.1 为什么非要有个映射器？

因为它要同时解决维度对齐和语义对齐两件事，而第二件才是关键。

维度问题好办，一层线性层即可。语义问题难，视觉编码器输出的向量分布与 LLM 文本嵌入分布无关，必须用图文数据训一个映射器把视觉特征翻译成 LLM 熟悉的形式。

映射器还兼着长度适配的活：视觉 token 通常远多于文本 token，得把视觉序列压到 LLM 能接受的规模。不想用映射器的话，就只能走原生多模态，让 LLM 直接吃 patch，但那要从头做大规模联合预训练，成本高一个量级。

### 3.2 映射器的输入输出和设计目标？

输入是编码器输出的视觉 token 序列，形状 `N × d_vision`；输出是 `M × d_llm` 的嵌入序列，M 可以等于也可以小于 N。

设计目标有四个：语义对齐，输出要落进 LLM 的语义邻域；长度可控，把 N 压到 LLM 能承受的 M；信息保真，压缩别丢关键细节，尤其是小字和位置；参数轻量，参数量相对 LLM 要可忽略，否则训练成本和过拟合风险都会上去。

### 3.3 映射器有哪几类？

按"是否压缩 token"和"用什么机制融合"两个维度分四类。

线性投影，一层 Linear，不压缩，LLaVA-1.0 用的就是它。MLP 投影，两层带激活，也不压缩，LLaVA-1.5 之后成了主流。查询式，比如 Q-Former 和 Perceiver Resampler，用一组固定数量的可学习 query 通过交叉注意力抽视觉信息，既压缩又融合。卷积式，用卷积或池化做局部下采样，保留空间邻接关系。

演进趋势很明显，从"只对齐不压缩"走向"对齐压缩一体"，因为 token 数才是推理成本的真正瓶颈。

### 3.4 一层线性投影够用吗？

小规模实验够，生产环境基本不会停在它上面。

它的优点是参数极少（百万级）、训练极快、几乎不需要额外数据，而且不引入信息瓶颈，视觉 token 一个不少地进 LLM，细粒度信息保留最好。缺点是不压缩也不融合：token 数等于 patch 数，长图会让 LLM 序列爆掉；而且只有线性变换能力，跨模态语义融合完全靠 LLM 自己去学。

适合数据量有限、追求最小改动接入的场景。图像分辨率本来就很低的时候（224×224 这类），它也不是不能凑合。

### 3.5 为什么换成两层 MLP 就有提升？

关键是引入了非线性。

线性映射只能做旋转、缩放、升维，MLP 能在视觉特征空间里做更灵活的重组。那为什么两层就够？因为映射器的任务是跨空间投影，不是学一个新任务，一层负责变换、激活提供非线性、第二层输出到目标维度，这个容量足够表达所需的映射。再往上加层增益很小，参数却线性增长，反而更容易在小数据上过拟合。

LLaVA-1.5 的消融验证过这一点：从线性升到两层 MLP 有稳定提升，继续加深收益递减。

### 3.6 Q-Former 压缩 token 的原理是什么？

用一组固定数量的可学习 query（一般是 32 个）去"提问"图像特征。query 之间做自注意力，同时通过交叉注意力读图像编码器的输出，最后输出固定 32 个 token。

压缩来源很直接，输出长度由 query 数决定，跟图像 patch 数无关，图多大多复杂出来的都是固定长度。它更重要的好处是跟 LLM 解耦：Q-Former 可以只用图文对单独训练，不需要 LLM 参与，训完把输出接到任意冻结的 LLM 上，所以 BLIP-2 能灵活换语言模型。

代价是 32 个 token 面对密集文本图信息容量不足，后来做文档理解的模型基本都放弃了这条路线。

### 3.7 卷积式映射器适合什么场景？

适合模态内部有强空间或时间邻接关系的输入，典型是视频、音频频谱、以及需要保留二维结构的场景。

原因是卷积自带局部性和平移不变性先验。视频里相邻帧、相邻区域高度相关，用卷积在时间和空间维同时下采样，能在压缩 token 的同时显式保留邻接结构，比让注意力从零学关系更省数据。

单张自然图像一般不选它，感受野受限又缺全局建模能力，更适合 MLP 或查询式。另外卷积式的压缩率是硬编码的，由 stride 决定，不像查询式能自由设定输出长度。

### 3.8 映射器里为什么要加位置编码？

因为视觉 token 是 patch 的集合，没有天然的先后顺序，不显式注入位置信息，模型看到的就是一袋无序的局部特征。

加了之后模型才能建立"左上角""右下角"的概念，进而支持空间关系推理、版面结构理解、坐标定位输出。实现上分绝对位置和相对位置两类，高分辨率模型多用二维或三维绝对位置编码。

放映射器之前还是之后都可以，但必须在视觉 token 进 LLM 之前注入。

### 3.9 模态类型编码解决什么问题？

它让 LLM 知道每个 token 来自哪个模态。

图像、文本、音频 token 被拼进同一个序列时，没有这个信号，模型会把视觉 token 当成某种奇怪的文本词去解释。不加的后果在多图场景下最明显：模型会把两张图的内容混着说，因为它判断不出哪些 token 属于第一张图。

实务上通常还要配一个模态分隔符把"类型"和"边界"分开表达，这样多图、图文交错的长上下文才稳定。

### 3.10 映射器能做多大？

量级上线性或 MLP 映射器是百万级，Q-Former 约一亿级，相比 LLM 的百亿级都可忽略，这正是它的设计初衷。

不该做太重有两个原因。一是训练数据是硬上限，映射器只靠图文对训练，数据规模远小于 LLM 的预训练语料，参数越多越容易过拟合到表面模式，表现就是训练集对答如流、换个说法就崩。二是它承担的是翻译而不是存储，如果映射器被迫背着大量语义知识，一旦换 LLM 就得重训，模块化解耦的好处就没了。

## 四、生成器

### 4.1 生成器在整体架构里干什么？

负责把 LLM 产出的语义表示还原成图像、音频、视频这些非文本信号，是理解链路的反向通道。

它跟编码器功能对称但不严格对称。编码器要提取语义、丢掉细节，生成器要从语义里重建设出细节，两者的信息需求正好相反，所以实践中很少直接复用同一个网络。

能被 LLM 驱动的生成器有几类：扩散或流匹配模型做文生图和图生视频，自回归图像 token 生成器属于统一自回归路线，神经声码器做文生语音。共同要求是接受一个语义条件向量并能稳定采样。

### 4.2 生成器的核心指标有哪些冲突？

可控性、保真度、一致性、推理效率，四个指标互相拉扯。

加引导强度能提升可控性，但会牺牲多样性、让画面发灰；减少采样步数提速会掉保真；加强帧间约束提升一致性，又会限制动态。

所以生成侧的设计从来不是"选最强的模型"，而是在这四个目标里找到匹配业务场景的那个点。

### 4.3 扩散模型为什么比 GAN 好用？

训练稳定，模式覆盖好。

它的训练目标是回归式的去噪损失，没有 GAN 那种判别器和生成器对抗导致的训练崩溃和模式坍塌，能覆盖到长尾的生成模式。代价是采样慢，原始 DDPM 要上千步，就算用 DDIM 加速到几十步，还是比 GAN 的单词前向慢一到两个数量级。

后面的一致性模型、蒸馏、流匹配，动机都来自这里。

### 4.4 自回归生成和扩散生成在争什么？

争的是"离散化统一"还是"连续生成"这两条假设。

自回归路线把图像也量化成离散 token，让同一个 Transformer 用下一个 token 预测同时做理解和生成，好处是架构彻底统一，理解与生成能互相促进，还能复用 LLM 的全部训练工程经验。扩散路线认为图像的信息密度远超文本，量化必然损失细节，而且逐 token 生成图像太慢。

现在的工业折中是混合路线：理解用连续视觉特征不量化，生成用扩散或流匹配。判断标准很实际，要统一架构选自回归，要生成质量和速度选扩散。

### 4.5 流匹配比扩散好在哪？

扩散学的是"从噪声逐步去噪"的随机路径，轨迹弯曲，所以必须走很多小步。

流匹配直接学从噪声分布到数据分布的速度场，把两者连成一条近似直线的路径。直线意味着可以用更少的采样步数走完，甚至一步到位。工程收益挺明显：训练目标形式简单，不需要精心设计噪声调度，推理步数与质量的关系也更友好。

SD3、FLUX 这些新一代模型转向流匹配就是这个原因。代价是理论上对分布形状的假设更强，训练不稳定时需要额外技巧兜底。

### 4.6 声码器是干什么的？

把低维声学特征还原成高采样率波形，是音频编码器的逆过程。

难点在相位重建。频谱本身不含相位信息，但人耳对相位错误极其敏感，所以声码器得从幅度谱里猜出合理相位。早期用 Griffin-Lim 迭代，效果机械刺耳，HiFi-GAN 之后用生成式方法直接合成波形，自然度才达标。

在语音大模型里它还有另一种形态：把 RVQ 产生的离散 token 序列解码成音频。一句话区分，编码器看"说了什么"，声码器管"好不好听"。

### 4.7 怎么让生成模型真的用上视觉信息？

最直接的诊断方法是遮挡实验。把图像换掉或者遮住关键区域，看输出变不变。不变就说明模型根本没在用视觉信息，此时优先要解决的是通路问题，不是知识问题。

训练侧能做的有：加 token 级监督，不只用整句对齐；在对比学习之外加重建或描述生成任务，重建逼模型保留细节，描述逼它语义准确；数据配比里保留纯文本，避免多模态数据把语言空间挤变形。推理侧可以在采样时放大视觉条件的权重，或者对视觉 token 的注意力做显式增强。

### 4.8 采样太慢有什么办法？

分两类。

训练无关的：高阶求解器（DPM-Solver 这类）能在保持质量的前提下把步数从 50 压到 10-20 步，性价比最高；缓存复用，相邻时间步的网络输出高度相似，缓存中间特征能省不少计算；还有量化和算子融合。

需要训练的：蒸馏类方法把多步教师压成少步学生，可以做到 1-4 步，代价是额外训练并轻微损失多样性；架构层面改用流匹配或在潜空间做扩散，直接降低计算量。

工程上一般先用求解器和缓存拿免费收益，再按需上蒸馏。

## 五、基石模型

### 5.1 CLIP 的前向流程说一下

两个独立编码器，图像塔是 ViT 或 ResNet，文本塔是 Transformer，各自输出一个向量，分别经线性投影到同一个维度 d，再做 L2 归一化。

一个批次取 N 组图文对，算出 N 个图像向量和 N 个文本向量，两两点积得到 `N×N` 的相似度矩阵，对角线是正样本对。训练目标是对这个矩阵按行和按列分别做交叉熵，也就是同时要求每张图找到自己的文本、每段文本找到自己的图。

温度系数是可学习的，由模型自己决定相似度的锐度。整个过程没有分类头，也没有生成解码器。

### 5.2 CLIP 为什么做成双塔而不是单塔？

因为双塔能离线索引，单塔做不到。

双塔不做跨模态交互，图像向量只依赖图像、文本向量只依赖文本，可以提前把所有图片编码好存进向量库，检索时只编码查询文本再做一次近邻搜索，规模上亿也没问题。单塔在编码阶段就让图文交互，表达能力强得多，但每对图文都得现场联合前向一次，检索时等于要对全库跑 N 次前向，完全不可行。

所以业界的做法是按任务分槽：检索用双塔，理解和推理用融合式 MLLM。CLIP 的价值在于给出了一套够好且可索引的表示，而不是最强的理解能力。

### 5.3 对比学习为什么适合大规模预训练？

三个原因。

监督信号免费。网页图文对天然存在，对比学习只需要知道"这一对是配的"，不需要任何人工类别标注。负样本批量生成，同一批次里其他样本就是负样本，一个 N 规模的批次提供了 N² 量级的监督信号。目标跟检索这个核心需求一致，模型学到的就是"在候选里排序"，正好是零样本分类和跨模态检索要用的能力。

相比之下分类式目标受限于固定类别体系、泛化不到新类；生成式目标信息量大，但模型会把大量容量花在语言流畅度上，还不如对比学习聚焦于语义对齐。

### 5.4 CLIP 的零样本分类怎么做？

把每个候选类别名填进一个句子模板（比如 `a photo of a {class}`），用文本塔编码所有类别句子，再用图像塔编码待分类图，取相似度最高的类别。

就这么简单。它不需要任何微调，也不需要见过这个类别的标注样本，这是 CLIP 最有价值的地方。

### 5.5 提示词为什么会影响零样本精度？

因为训练时的文本是自然句子，推理时如果只喂一个孤零零的类名词，文本就会掉出训练分布。

模型没见过"cat"这个短语的独立用法，它见过的是"a photo of a cat"。另外类名本身有歧义，比如 boxer 既是拳击手也是狗，包进模板之后上下文才能消歧。

CLIP 论文里用了几十套模板做 ensemble 平均，比单个模板的零样本精度有明显提升，是个很便宜但有效的技巧。

### 5.6 CLIP 有哪些绕不过去的局限？

不支持生成，这是结构性的，只有两塔编码器没有解码器，输出不了图像或长文本。

细粒度和空间关系弱，对比损失只看整图对整句，不约束哪个词对应哪个区域，所以计数、"左边右边"、属性绑定判别接近随机。文本理解浅，训练文本是短标题式描述，遇到长句、否定、条件推理就下降。还有就是数据噪声和偏置，直接从网络爬取，继承了错误对齐和社会偏置。

后续模型的改进路线正好对应这四条。

### 5.7 BLIP 的 MED 结构是什么？

多模态编码-解码混合，三种模式共享同一套 Transformer 参数，靠不同的自注意力掩码切换。

单模态编码器，图像和文本各自独立编码互不可见，对应图文对比。图-文编码器，文本可以双向关注图像但图像不关注文本，输出融合表示，对应图文匹配。图-文解码器，用因果掩码做自回归生成，图像可通过交叉注意力被文本看到，对应图像描述和问答生成。

一份参数同时承担对比、匹配、生成三类目标，比单目标模型泛化更好。

### 5.8 ITC、ITM、LM 三个目标各管什么？

分工挺清楚。

ITC 在单模态编码器上做，学的是够用的粗略对齐，负责把图文拉进同一个空间、支撑检索，便宜高效但缺细粒度。ITM 在图-文编码器上做，用一个二分类头判断图文是否真配，这是细粒度的，它必须逐区域核对，补上了 ITC 的短板。LM 在图-文解码器上做，赋予模型生成能力。

ITM 的关键技巧是难负样本挖掘：负样本不随机取，而是取同一批次里 ITC 相似度最高的那些错配样本，逼模型学细微差别，否则任务太简单什么也学不到。

### 5.9 CapFilt 是怎么清洗数据的？

CapFilt 等于 Captioner 加 Filter，解决的是网络图文对里文本质量太差这个痛点。

网页图片旁边的文字往往是文件名、广告、无关正文，直接拿来训练等于教模型错误对齐。Captioner 是图像描述模型，给每张图重新生成一条合成描述，替换或补充原始噪声文本；Filter 是图文匹配模型，逐条判断图加文本是否真配，不配的丢弃。

两者先在人工标注数据上训练，再应用到网络数据上做清洗，得到高质量数据集后回来继续训模型。这是个自举循环，每轮数据质量都提升一点，后来成了多模态数据工程的通用范式。

### 5.10 BLIP 比 CLIP 强在哪？

CLIP 是个纯判别式的排序器，它能告诉你这张图和哪段文本最配，但输出不了新文本，也做不了区域级判断。

BLIP 因为引入了图-文编码器（可做二分类匹配）和图-文解码器（可自回归生成），能力扩展到检索、描述生成、视觉问答三类。检索上通常也优于 CLIP，因为 ITM 的难负样本挖掘带来了更精细的判别能力，可以在 ITC 粗筛之后做一轮精排。

但要清楚，BLIP 的生成能力是在图像描述任务上训出来的，只能产出短描述，不具备对话和指令跟随能力，那是 LLaVA 这一代才解决的事。

### 5.11 BLIP-2 为什么要冻结两头？

动机是用最少的可训练参数量把两个已经很强的冻结模型接起来。

可训的只有 Q-Former 约一亿参数，相比联合训练百亿级模型成本低了两个数量级，而且不会破坏图像编码器的视觉能力和 LLM 的语言能力。第二个好处是 LLM 可插拔，Q-Former 只用图文对训练，输出的 32 个 query token 本质上是一段视觉前缀，可以接到任何同维度的 LLM 上。

代价是 32 个 token 容量有限，面对密集文本或细粒度推理力不从心，而且两段式训练让视觉信息必须先完整压缩进 Q-Former 再交给 LLM，中间的信息瓶颈绕不过去。

### 5.12 LLaVA 只有三段，凭什么有效？

数据流是图像经 ViT 编码得到视觉 token，投影器映射到 LLM 嵌入维度，与文本 token 拼成一条序列，送进 LLM 自回归生成回答。

它之所以有效，是因为把 LLM 放在了核心位置。视觉部分只负责提供信息，所有推理、知识、对话能力全部复用 LLM 已有的语言先验，投影器力求简单，不去做复杂的视觉理解。训练只需要教会模型"如何看"，而不必重新教它"如何思考"，所以数据量需求比从头联合预训练低一到两个数量级。

代价是视觉细节的损失只能靠提高分辨率和减少压缩来补，LLM 的语言偏见也可能压过图像证据。

### 5.13 LLaVA 的两阶段训练分别干什么？

第一阶段是特征对齐，冻结视觉编码器和 LLM，只训投影器，数据约 59 万条图文对（主要来自 CC3M，转成"描述这张图"的形式），目标是让视觉 token 落到 LLM 的语义邻域。

第二阶段是指令微调，解冻 LLM 或用 LoRA，数据约 15 万条多模态指令，涵盖对话、细节描述、复杂推理三类，目标是让模型学会按指令用图。

顺序不能反。没有第一阶段，视觉 token 还是乱码，直接做指令微调等于让它学一门没有字母表的语言。

### 5.14 为什么用 GPT-4 合成指令数据是神来一笔？

因为当时多模态指令数据几乎没有现成来源，人工标注成本高且规模上不去。

LLaVA 的做法是把图像的文本表示（描述加检测框）喂给纯文本 GPT-4，让它按预设的几种题型（对话、详细描述、推理）生成问答对。只用了语言模型就造出十几万条指令数据。之所以有效，是因为知识在语言空间里已经存在，图像只是触发器。

风险也很实在：合成数据的语言风格单一，模型会学到 GPT-4 的表达习惯；而且如果文本表示本身漏了图中细节，合成数据里就永远没有这些细节。

## 六、系列模型拆解

### 6.1 Qwen-VL 的三阶段训练怎么排的？

第一阶段预训练，冻结 LLM，只训视觉编码器和适配器，数据约 14 亿图文对，建立基础对齐。第二阶段多任务预训练，解冻 LLM，引入约 7800 万条更高分辨率的交错图文数据，同时加入 OCR、定位、检测这些需要细粒度的任务。第三阶段 SFT，约 35 万条问答数据做指令微调。

排序逻辑是"先对齐、再注入能力、最后调行为"。第一阶段如果不冻结 LLM，视觉的随机梯度会把语言能力冲坏；第二阶段必须解冻，否则 LLM 学不会使用视觉信息；第三阶段数据量最小但质量最高，负责把前两阶段的能力收敛成可用的交互行为。

### 6.2 M-RoPE 为什么要拆成三分量？

因为它要解决图文视频混合输入下位置信息没法用一维表示的问题。

传统做法把视觉 token 拍平成一维编号，模型知道"第 537 个 token"，但不知道它在第几行第几列，空间关系推理和坐标定位就无从谈起。M-RoPE 把位置编码拆成时间、高度、宽度三个分量：图像的时间分量恒定，高宽分量按 patch 的二维网格变化；视频三个分量都用上，时间分量沿帧递增。文本的三分量取相同值，退化成普通一维。

好处是模型能直接从位置编码读出二维或三维结构，支撑了原生动态分辨率和视频时序推理。

### 6.3 Qwen-VL 为了吃高分辨率做了什么？

三件事。

一是原生动态分辨率，不把图缩放到固定尺寸，按原始宽高切 patch，token 数随内容自适应，配合 M-RoPE 提供二维位置信息，文档、表格、密集小字的识别率直接上来了。二是视觉塔改用窗口注意力，把 ViT 里的全局注意力换成局部窗口，避免高分辨率下注意力的平方开销。三是主干组件现代化，用 RMSNorm、SwiGLU、QKV bias 替换传统实现。

这个组合思路挺有代表性：先让输入真高分辨率，再让编码器扛得住，最后压输出 token 数。

### 6.4 框坐标为什么要写成文本？

思路是把坐标变成 token，训练模型输出 `<box>(x1,y1,x2,y2)</box>` 这样的序列，让定位变成语言建模问题。好处是不需要额外的检测头，还能跟自然语言描述自由混合。

坐标表示反复调是因为每种选择都踩坑。归一化坐标（0-1 小数）精度差、小数位数长且不整齐，token 效率低；绝对像素坐标数值范围随图像尺寸变化，泛化差；千分制整数（0-1000）折中了好处，整数 token 切分干净、范围固定、精度够用，成了主流。

但有个前提不能忘：定位精度本质上受限于视觉 token 的分辨率。1000×1000 的图只压到 256 个 token，每个 token 覆盖的区域很大，模型物理上不可能输出精确坐标。

### 6.5 InternVL 的渐进式对齐是什么思路？

思路是别一上来就把视觉塔和一个大 LLM 绑在一起训。

做法是分步走：先用一个较小的语言模型训好视觉编码器和映射器，让视觉侧先学会往语言空间靠；等视觉表示质量稳定后，再迁移到更大的 LLM 上做联合训练。背后的道理是视觉编码器的对齐过程需要大量迭代，一开始就挂在最大最贵的 LLM 上，试错成本高得离谱；而视觉对齐一旦完成，对 LLM 规模的依赖其实不强。

收益是总训练成本明显下降、过程更稳，算力受限时也更容易给出可交付的中间版本。

### 6.6 内容自适应压缩怎么落地？

先判断图像的信息密度，再决定压多少 token。用一个轻量模块（特征统计或一个小网络）给图像打分，简单自然图归入低分辨率通道压得更狠，文档和密集目标图走高清通道保留更多 token。

重要性在于固定压缩率两头都亏，按简单图设上限文档图会丢字，按文档图设上限普通图片白白吃掉几倍算力。内容自适应等于给每张图分配了与信息量匹配的算力预算。

取舍在于路由本身的成本必须极低。如果判断复杂度要跑一遍完整编码，省下来的算力就全赔回去了，所以实践中多用简单的可学习门或统计量做粗分，不用精细分类器。

### 6.7 原生预训练和"缝合式"改装差在哪？

三处。

训练起点不同，改装路线从一个训好的 LLM 出发接视觉，原生路线从随机初始化开始让视觉和语言一起长。数据配比不同，改装路线的训练数据几乎全是图文对，语言能力靠 LLM 原有的；原生路线必须按比例混合大规模纯文本语料，否则语言能力会退化，这个配比是原生训练最关键的工程参数。冻结策略不同，改装路线大量冻结来省成本，原生路线全程全参数训练，视觉与语言才能在深层真正融合。

选型上，改装路线便宜、见效快、能复用最新 LLM，是绝大多数团队的现实选择；原生上限更高但需要千万级图文对加大规模纯文本加大量算力。我的建议是，除非有自有数据壁垒和充足算力，否则从改装起步并逐步解冻，性价比最高。

### 6.8 GLM-V 那套推理型多模态能学什么？

值得借鉴的地方有几处。

它把长链推理引入多模态问答，模型先输出一段思考过程（拆解题目、检查图中证据、自我验证）再给答案。训练上它不用监督微调去模仿推理格式，而是用强化学习优化推理质量，因为模仿只能学到形式，强化学习才有可能让模型学会"什么时候该多看一眼图"。奖励设计坚持可验证原则。数学题、图表数值题、坐标定位题这类有确定答案的任务可以用规则或代码判分，奖励信号干净不容易被刷；开放式视觉描述题就很难验证，容易导致钻空子。

可迁移的结论是：优先为可验证的多模态任务做 RL，开放任务仍以 SFT 为主。

### 6.9 推理型多模态常见怎么翻车？

三种。

重复生成，长推理链里模型陷入复制前文，输出同一句话直到超长，一旦进入循环就很难靠采样参数救回来。看图即弃，思考过程写得头头是道但结论与图像无关，根子在模态鸿沟，模型宁可相信语言先验，诊断方法还是遮挡或替换图像看输出变不变。过度思考导致漂移，推理链越长，中间一步的错觉会被后面反复放大，最后给出自信但错误的答案。

这三条的共同点是，多模态推理的失效大多不是知识不够，而是信息通路没打通。

## 七、原生架构与落地

### 7.1 怎么判断一个模型是不是"真原生"？

三条可操作的判据。

一是训练起点，是否从随机初始化开始联合训练，而不是从已训好的单模态模型拼接。二是数据配比，训练语料里有没有按比例混合大规模纯文本与多模态数据，这是硬指标，因为只有联合训练才需要处理这个配比问题。三是模态对称性，理解与生成是否用同一套表示，而不是理解一个模型、生成再挂一个。

要顺带区分三个概念：原生多模态强调训练方式，全模态（Omni）强调覆盖的模态数量，统一理解生成强调任务范围。三者可以独立成立。市面上很多宣称"原生"的模型其实只是在预训练末期加了点多模态数据，第二条判据最能戳穿这一点。

### 7.2 缝合式路线的天花板在哪？

三处。

信息瓶颈。视觉信息必须先在编码器和映射器里压缩成固定长度序列再交给 LLM，后面的 LLM 无论多强，也只能基于这个已经压缩过的表示推理，图上被压掉的细节永久丢失。这也是原生动态分辨率加减少压缩成为主流改进方向的原因。

对齐不深。编码器是冻结或轻微微调的，它的参数分布由图像目标决定，与 LLM 的深层语义需求并不一致；只在浅层做映射，意味着跨模态融合只能发生在 LLM 的前几层。

难以统一生成。理解要抽象语义、生成要保留细节，两者对表示的要求相反，模块化架构里生成通常要另挂一个扩散模型，"理解强但画不出来"成了通病。

### 7.3 理解要的表示和生成要的表示为什么打架？

因为理解需要不变性，生成需要等变性。

理解的理想表示对无关变化不敏感，猫在图的哪个位置、什么姿态，都应该归到"猫"这个语义上，所以编码器会主动丢弃位置、尺度、纹理细节。生成要的正好相反，它必须知道每个像素的确切位置和颜色才能重建图像，任何被丢弃的细节都是永久损失。

举个例子，"把这张图里的杯子右移 3 厘米"，理解侧只关心"有杯子"，生成侧必须精确知道每个像素该往哪搬。调和方案有两类：解耦双表示，同一主干在末端分出语义分支和细节分支；分层表示，低层特征用于生成、高层特征用于理解。到现在没有一个方案真正解决，还是开放问题。

### 7.4 多模态落地有四条路，怎么选？

按成本从低到高：提示工程、多模态 RAG、微调、蒸馏。

提示工程不训模型，靠设计指令、few-shot 示例、思维链约束输出格式，成本几乎为零，任务清晰且模型能力够用就先试这条。多模态 RAG 针对的是模型能力够但缺私有知识的情况，难点在图文对齐检索，不是文本检索那套老问题。微调用于模型能力不足或领域分布偏移严重（医学影像、工业质检），需要几百到几千条高质量样本。蒸馏是效果达标但成本时延不允许时，把大模型能力压到小模型上。

决策顺序应该是先提示、再 RAG、再微调、最后蒸馏。每一步都先量化评估当前瓶颈是缺知识还是缺能力，别一上来就微调。

### 7.5 多模态 RAG 和文本 RAG 差在哪？

检索单元不一样。文本 RAG 切段落，多模态 RAG 要切"图文块"，一张图加它的标题和正文引用必须保持在一起，切开了图就没语境。

检索方式不一样。文本检索用文本 embedding 就够，多模态检索必须用跨模态向量才能用文字查图，但跨模态相似度的绝对阈值不可靠，通常需要"文本检索粗筛加跨模态精排"两级组合。

上下文利用也不一样。图文交错的长上下文对位置极其敏感，塞进 LLM 时的顺序、分隔符、模态标记都会显著影响回答质量；而且图本身占的 token 远多于文本，检索数量必须更保守。另外文档场景里版面结构是关键，表头与单元格的对应、图注的归属，这些在纯文本 RAG 里根本不存在。

### 7.6 多模态幻觉怎么治？

分三层。

数据层，清洗图文对里的错误对齐，在指令数据里显式加入"图中没有该信息"的回答样本，教模型承认看不见。这比教它编造更难也更值钱。训练层，加大 token 级视觉监督，用 DPO 或 RL 对幻觉样本做负向偏好优化。推理层，提高有效分辨率（大量幻觉源于看不清）、用受限解码要求先引用证据再回答、或者让模型复述图中证据再给结论。

诊断上一律用遮挡实验和反事实测试。遮住关键区域或替换图像，如果回答不变，说明模型没用视觉证据，此时该优先解决通路问题而不是知识问题。

### 7.7 什么情况下不该上多模态大模型？

四类场景绕开它比较好。

任务高度确定且量极大，比如固定格式的票据字段抽取、流水线缺陷分类，用专用小模型或传统 CV 加 OCR 模板精度更高，成本低一到两个数量级，MLLM 在这儿属于高射炮打蚊子。要求像素级精度的测量类任务，尺寸测量、亚像素缺陷定位，MLLM 输出的坐标精度撑不住判定。强实时且算力受限的场景，端侧或高并发，推理时延和显存都过不了门槛。本来只有文本的任务，硬套多模态只会增加成本和幻觉风险。

判断标准可以简化成一句话：这个任务是不是需要"开放式语义理解加灵活的自然语言输出"？需要就用 MLLM，不需要就老老实实用专用方案。
