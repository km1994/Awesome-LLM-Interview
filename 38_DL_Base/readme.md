## 一、基本概念

### 1.1 AI、机器学习、深度学习三者是什么关系？

层层包含。

人工智能是最外层目标，让机器表现出智能行为，早期靠专家规则实现，不需要从数据学习。机器学习是其中一条实现路径，不写死规则，而是从数据里归纳规律，代表方法有决策树、SVM、集成学习。深度学习是机器学习的子集，用多层神经网络自动学分层特征表示，代表方法有 CNN、RNN、Transformer。

关键区别在特征从哪来。传统机器学习要人工设计特征，HOG、SIFT 这些；深度学习把特征提取也交给模型自己学。所以深度学习不等于 AI，AI 的大部分应用到现在仍然由非深度学习的方法支撑。

### 1.2 单层感知机的本质局限是什么？

它只能解决线性可分的问题。

感知机是使用阶跃函数作激活的最简单神经元，计算形式是 `y = f(Σ wᵢxᵢ + b)`。偏置 b 的作用是平移决策边界，没有它的话输入全零必然输出固定值，模型的表达自由度会被削弱。

经典反例是 XOR，异或问题无法用一条直线分开。这个局限的解法不是换激活函数，而是堆叠多层：加入隐藏层后，网络可以先用多个线性边界组合出中间表示，再在输出层做线性组合，从而实现非线性可分。这正是"深度"的意义，也是后面所有深度模型的理论起点。

### 1.3 万能近似定理说了什么？前提是什么？

定理说的是，只要隐藏层神经元足够多，含单个隐藏层的前馈网络可以以任意精度逼近任意连续函数。

但三个前提必须说清。定理只保证存在这样一组参数，不保证能找到，因为优化问题非凸，梯度下降可能陷入次优解。它只保证逼近能力，不保证泛化能力，拟合能力过强反而容易过拟合。它说的是宽度，而实践中选择深度是因为深层网络用少得多的参数就能表达同样复杂的函数，层级组合带来指数级的表达效率，而且更符合数据的层次结构。

这就是"深层优于单层宽"的原因，也是面试里最容易被追问的点。

### 1.4 参数量和 FLOPs 有什么不一样？

参数量是模型里可学习权重的数量，决定显存占用，FP16 下一个参数占 2 字节。FLOPs 是一次前向传播需要的浮点运算次数，决定计算时间。

两者都要看，因为对应不同瓶颈。参数量大但计算量小的例子是全连接层参与大量低维运算的模型，属于访存密集；计算量大但参数量小的是小卷积核配大空间尺寸的网络，属于计算密集。部署时显存不够看参数量，速度不够看 FLOPs。

还有个容易忽略的维度是激活值大小，它决定训练时的显存峰值，往往比参数量更致命。

### 1.5 训练集、验证集、测试集怎么划？

训练集更新参数，验证集选超参和早停，测试集只用于最终评估，在整个开发过程中不能用来做任何决策。

最常见也最严重的误用是用测试集反复调参。每调一次就偷看一次测试集，迭代几十轮之后测试分数就变成了乐观偏置，无法反映真实泛化能力，这在学术论文里也挺普遍。

数据量小时用 K 折交叉验证，把训练数据分成 K 份，轮流用其中一份做验证、其余训练，最后取平均；要同时调超参和评估就用嵌套交叉验证。另外划分必须保证数据分布一致，时间序列按时间切分不能随机打乱，否则会引入未来信息泄漏。

### 1.6 过拟合欠拟合怎么判断、怎么治？

看训练集和验证集损失的差距。

训练低、验证高是过拟合，模型记住了训练数据的噪声。两个都高是欠拟合，模型容量不足或训练不充分。过拟合的对策是加数据或做增强、加正则化、降容量、早停、集成；欠拟合的对策是加容量或层数、减正则、延长训练、检查学习率是不是太小、检查输入信息本身够不够。

关键认知是两者是权衡关系，模型容量是同一个旋钮的两端。所以正确顺序是先确保不过拟合（把容量用足并加正则），再确保不欠拟合。反过来会导致在欠拟合时就去调正则，越调越差。

还有个高频误区：把验证集不涨直接判为过拟合。其实也可能是学习率调度问题或数据分布不一致，要结合训练曲线形态判断。

### 1.7 偏差-方差分解在指导什么？

模型的总期望误差可分解为偏差平方、方差、还有不可约噪声。

偏差衡量模型的系统性错误，真实规律没被拟合到，表现为训练误差高（欠拟合），随模型复杂度上升而下降。方差衡量模型对训练集随机性的敏感程度，换一批数据结论就变，表现为训练误差低但验证误差高（过拟合），随复杂度上升而升高。不可约噪声是数据本身的随机性，建模消除不了。

工程指导有三条。看到验证误差高，先看训练误差来判断是偏差主导还是方差主导，训练误差也高就是偏差问题，很低就是方差问题。数据量增加会降低方差但不降低偏差，所以"数据不够"和"模型太小"需要不同解法。这也解释了为什么大模型在小数据上表现差，容量大导致方差极高，此时应该用预训练加微调而不是从头训练。

### 1.8 梯度为什么会消失和爆炸？

反向传播是多层雅可比矩阵连乘。每层梯度的谱范数小于 1 时，连乘后梯度随层数指数衰减；大于 1 时指数放大。

影响因素有三个。激活函数方面，Sigmoid 和 Tanh 的导数最大为 0.25 和 1，多层连乘必然衰减，饱和区导数趋近 0 更是雪上加霜。权重初始化方差偏小或偏大会分别放大衰减与爆炸。网络深度越大连乘次数越多，问题越严重。

解法有几条：换激活函数（ReLU 在正区间导数恒为 1，这是深度学习能变深的关键之一）；合理初始化（Xavier 针对 Tanh 和 Sigmoid，He 针对 ReLU，核心思路是让每层输出方差保持稳定）；归一化层把每层输入分布拉回稳定区间；残差连接给梯度提供恒等通路，这是 ResNet 能训到上百层的原因；梯度裁剪专门解决爆炸。

### 1.9 归一化层有哪几类？BN 和 LN 差在哪？

区别在沿哪个维度统计均值和方差。

BatchNorm 对一个批次内、同一通道的所有空间位置做统计，依赖批次维度，所以 batch 小时统计不准，而且训练与推理行为不一致，推理时要用滑动平均的统计量，这在序列长度变化的 NLP 任务上很难用。LayerNorm 对单个样本内部的所有特征维度做统计，不依赖批次，训练与推理完全一致，所以成了 Transformer 的标准配置。InstanceNorm 对单个样本的单个通道统计，常用于风格迁移。GroupNorm 把通道分组、组内统计，是在 batch 很小（检测分割任务受显存限制只能开小 batch）时替代 BatchNorm 的折中方案。

一句话选择逻辑：NLP 用 LayerNorm，CV 大 batch 用 BatchNorm，CV 小 batch 用 GroupNorm。

## 二、网络层体系

### 2.1 卷积和互相关是一回事吗？

数学上不是。真正的卷积要先把核翻转 180 度，再和输入做滑动加权求和；而框架里 `Conv2d` 实际实现的是互相关，不翻转。

之所以能这么干，是因为卷积核是可学习的，翻转与否只相当于换了一套参数，模型有能力学到等价结果，所以工程上选了计算更简单的互相关。

这个区别在理论推导时很重要，比如和信号处理里的频域卷积定理对应。做与已有实现严格对齐的复现工作时也必须确认翻转约定，否则数值对不上。

### 2.2 输出尺寸和感受野怎么算？

输出尺寸是 `H_out = floor((H_in + 2×padding − dilation×(k−1) − 1) / stride) + 1`。

四种常见配置：`stride=1, padding=(k−1)/2` 保持尺寸不变，也就是 same padding；`stride=2, k=3, padding=1` 尺寸减半；空洞卷积通过增大 dilation 扩大感受野但不增加参数；`k=1` 的 1×1 卷积只做通道变换不改空间尺寸。

感受野指输出上一个点对应输入上的区域大小，递推公式是 `RF_out = RF_in + (k−1) × 累计 stride`，累计 stride 是前面所有层 stride 的乘积。理解感受野的实用价值在于：浅层感受野小、只看局部纹理，深层感受野大、能看到语义结构，这就是 CNN 分层特征的来源。它也解释了为什么小目标检测需要额外的高分辨率分支，因为小目标在深层的大感受野里只占几个像素，信息已经被稀释了。

### 2.3 常见的卷积变体解决什么问题？

六种常见变体。

1×1 卷积不改变空间尺寸，只做跨通道融合与通道数升降维，是瓶颈结构的核心，也常用来降维减少后续计算量。深度可分离卷积把标准卷积拆成逐通道的空间卷积加 1×1 的通道融合，参数量和计算量能降到标准卷积的九分之一左右，是移动端网络的基石。空洞卷积在核元素间插入间隔，不增加参数就扩大感受野，代价是产生网格伪影，常用于分割。转置卷积用于上采样，做法是把前向卷积的梯度运算当成前向，会产生棋盘格效应，改进方案是插值上采样加普通卷积。分组卷积把通道分成若干组、组内独立卷积，参数量和计算量按组数成比例下降，代价是组间信息不流动，ResNeXt 与深度可分离卷积都是它的特例。可变形卷积让采样位置本身可学习，能适应不规则形状，对形变目标效果好但实现复杂、不友好于加速。

### 2.4 池化的作用是什么？反传怎么算？

池化有两个作用：降低空间分辨率，减少后续计算量与显存，同时提供一定的平移不变性；扩大感受野，在深层间接放大有效感受野。

最大池化的反向传播是前向时记录每个窗口内最大值的位置，反向时梯度只回传给那个位置、其余为零，相当于梯度路由。平均池化则把梯度均分给窗口内所有位置。

全局平均池化把整张特征图空间维度平均成 1×1，直接接分类头，好处是大幅减少参数量并降低过拟合风险。但要注意池化会丢失精确的位置信息，所以检测、分割这类需要定位的任务往往用 stride 卷积代替池化。

### 2.5 CNN 凭什么能用那么少参数处理图像？

靠局部连接和权重共享两个机制。

局部连接让每个输出只连接输入的局部区域，而不是像全连接那样连接全部输入，利用了"图像中相邻像素高度相关"这个先验。权重共享让同一个卷积核在整张图上滑动复用，使得参数量与图像尺寸无关，这是关键：全连接层处理 224×224×3 的输入，第一层参数量就有数千万量级，而一个 3×3×3×64 的卷积核只有 1728 个参数。

这两个机制合起来就是平移等变性这个归纳偏置，物体平移时输出特征图也随之平移，模型不必在每个位置重新学一遍。代价是这个先验假设很强，当数据模式不满足局部性和平移不变性时（需要全局建模的语义推理、图数据、点云），CNN 反而不如通用架构。这也解释了 Vision Transformer 为什么需要海量数据才能追上 CNN。

### 2.6 Dropout 训练和推理为什么行为不同？

训练时以概率 p 随机把一部分神经元的输出置零，并把保留的神经元输出除以 (1−p) 作缩放。置零是为了打破神经元之间的共适应，缩放是为了保持下一层输入的期望值不变，否则置零会系统性地降低激活量级。

推理时不做随机置零，也不做缩放，因为训练时已经缩放过，期望一致。另一种等价实现叫 inverted dropout，在训练时缩放、推理时不缩放，这也是框架的默认实现，好处是推理路径完全不增加开销。

Dropout 之所以被视为一种模型集成：每次置零得到的是一个不同的子网络，训练过程等价于训练指数级数量的子网络并共享权重，推理相当于这些子网络的平均，而平均能降低方差。

### 2.7 残差连接到底解决了什么？

解决的是退化问题。在它之前，把网络简单加深，训练误差不降反升。

注意这和梯度消失不是一个问题。梯度消失是梯度太小导致学不动，而退化问题在用了 BatchNorm 的网络里依然存在，说明深层网络的优化景观本身很难找。

残差连接让每层只学残差 `F(x) = H(x) − x`，最终输出 `H(x) = F(x) + x`。两条价值：一是让恒等映射变得容易，某层没用的话网络只需把 F 学成零，而不用学一个复杂的恒等变换，等于给了网络"跳过无用层"的默认选项，加深网络最差也不会变坏；二是提供梯度高速公路，反向时 `∂H/∂x = ∂F/∂x + 1`，那个常数 1 保证梯度能原样跨层回传，无论 F 的梯度多小。

这两点合起来让上百层网络可以稳定训练，也是 Transformer 里每个子层都带残差的原因。

### 2.8 权重初始化为什么不能全零？

因为对称性。同一层内所有神经元的权重完全相同，它们接收相同输入、产生相同输出、收到相同梯度，更新后依然完全相同，等价于整层只有一个神经元，模型表达能力被摧毁。

随机小方差初始化也不安全。太小会导致信号逐层衰减，太大则逐层放大，激活饱和。正确思路是控制方差，让每层的输出方差与输入方差相当。Xavier 按 `1/(fan_in + fan_out)` 量级设定，适合 Tanh 和 Sigmoid；He 初始化按 `2/fan_in` 设定，因为 ReLU 会把一半神经元置零、方差减半，需要双倍补偿。

现代大模型还有两条实践：用非零的小常数缩放残差分支输出，避免深层残差累加导致方差爆炸；以及用固定的正态初始化配合稳定的归一化层（RMSNorm、Pre-LN）降低对初始化精度的依赖。这也是现在训练几十层 Transformer 比当年容易得多的原因之一。

### 2.9 L1 和 L2 正则差在哪？为什么 L1 稀疏？

L2 在损失里加 `λΣw²`，梯度是 `2λw`，与权重大小成正比，权重越大惩罚越强，效果是把权重整体压小但很少压到零，让模型更平滑、对输入扰动更鲁棒。

L1 加 `λΣ|w|`，梯度是 `λ·sign(w)`，与权重大小无关。无论权重多小，每步都受到同样大小的推力，所以小权重会被直接推到零，产生稀疏解，可兼作特征选择。

几何直觉是：L1 的约束区域是菱形，有尖角，最优解容易落在坐标轴上的顶点；L2 的约束区域是圆形，没有尖角，最优解一般不在坐标轴上。

还有个术语差别要注意。权重衰减在标准 SGD 里等价于 L2，但在自适应优化器里两者不同，Adam 会按梯度二阶矩归一化，导致 L2 惩罚对不同量级的权重作用不均。所以 AdamW 的做法是解耦权重衰减，直接把权重乘以衰减因子而不是加进梯度。

### 2.10 为什么要 warmup？

因为固定学习率无法兼顾训练前后：初期离最优点远，需要较大步长快速下降；后期接近最优点，大学习率会在最优附近震荡甚至发散。

常见调度策略有 Step decay（固定里程碑处衰减，简单但需手工设定）、Cosine decay（平滑衰减到接近零，目前最常见）、Linear decay、OneCycle（先升后降）。

warmup 指训练最初若干步从接近零的学习率线性升到目标值，作用有两个。一是避免初期的大梯度破坏参数，训练开始时参数随机、损失面陡峭，而且自适应优化器的二阶矩估计还没稳定，早期方差估计误差极大，会导致更新步长异常大，此时大学习率容易一步把参数推到坏区域甚至造成 loss 爆炸。Transformer 训练尤其敏感，因为它没有 BatchNorm 这类稳定机制。二是让自适应优化器的统计量收敛，Adam 的前几步需要积累梯度信息才能给出合理的更新量。

实践上大模型的典型配置是几百到几千步 warmup 加余弦衰减，warmup 时长按总训练量比例设定。

## 三、序列与图

### 3.1 RNN 的梯度问题是什么？LSTM 怎么缓解？

RNN 的隐藏状态沿时间步递推 `h_t = f(W_h h_{t-1} + W_x x_t)`，反向传播要对时间步连乘，所以梯度随序列长度指数衰减。这就是长程依赖学不动的根因。

LSTM 的关键设计是引入细胞状态这条"传送带"和三个门：遗忘门决定丢弃多少历史，输入门决定写入多少新信息，输出门决定暴露多少给下一层。细胞状态的更新形式是 `C_t = f_t ⊙ C_{t-1} + i_t ⊙ C̃_t`，其中的加法路径让梯度可以近似恒等地沿时间传播，类似残差连接的作用，大大缓解了梯度消失。

但它没有彻底解决问题。门控只是让梯度衰减变慢，超长序列依然学不好；而且递推结构无法并行，训练效率低。这两条正是 Transformer 取代 RNN 的原因。

### 3.2 RNN、LSTM、GRU 怎么选？

RNN 最简单，只有一个隐藏状态，无门控，参数量最少但长程建模最差。LSTM 有细胞状态加三个门，参数量约为 RNN 的 4 倍，长程建模最好但计算最重，还要同时维护 h 和 C。GRU 是 LSTM 的简化版，把细胞状态与隐藏状态合并，三个门减为重置门和更新门两个，参数量约为 LSTM 的 3/4，性能在多数任务上与 LSTM 相当甚至更好，收敛更快。

现在三者在主流 NLP 场景基本都被 Transformer 取代了，RNN 系只剩三类适用场景：流式或在线推理（需要逐 token 增量处理、不能看到未来，RNN 的 O(1) 状态是天然优势）、资源极度受限的端侧、序列很短且任务简单。

如果必须选一个，默认 GRU，它在效果和成本之间最平衡。

### 3.3 从 RNN 到 Transformer 的驱动力是什么？

两个。

长程依赖建模质量。RNN 系的信息必须逐时间步传递，路径长度 O(n)，梯度在传递中衰减；自注意力让任意两个位置直接相连，路径长度降为 O(1)，长程信息不再衰减。

训练并行度。RNN 的时间步必须串行，无法利用 GPU 的大规模并行，序列越长训练越慢；自注意力在训练时可以一次看到全部序列，把整个序列的计算变成矩阵乘法，充分利用并行算力。

合起来看，这两点让 Transformer 有能力吞下海量数据。它赢在能算，不在聪明。代价是复杂度从 O(n) 变成 O(n²)，序列越长计算和显存开销增长越快，这催生了大量高效注意力研究。

### 3.4 CNN 和 Transformer 的归纳偏置差在哪？

CNN 带两类强归纳偏置：局部性（相邻像素相关，所以只看局部窗口）和平移等变性（同一模式在不同位置应被同样处理，所以共享权重）。这两个假设对自然图像极其有效，所以 CNN 在小数据上就能学好。

Transformer 几乎没有这些偏置。自注意力对所有位置一视同仁，只有位置编码提供顺序信息，也不假设局部相关，所以它是更通用但更"白板"的架构。

这直接决定了数据量要求。CNN 靠先验弥补数据不足，Transformer 必须先用数据把先验学回来。Vision Transformer 早期的关键结论就是这个：在中等规模数据上打不过 CNN，只有到了数亿张图的量级才反超。同理，Transformer 在大规模数据上的上限更高，因为它不受"图像是局部相关的"这一假设限制，能学到 CNN 结构上无法表达的全局关系。

### 3.5 为什么需要图神经网络？

图数据有三个特性让常规网络难以处理。非欧几里得结构，节点邻居数量不定、没有固定网格，卷积核无法定义"固定大小的窗口"。邻居数量变长，同一层里每个节点的邻居数从 1 到几千不等，无法组织成固定张量。无序性，邻居之间没有天然顺序，模型输出不应依赖邻居的排列顺序。

直接套用会遇到具体问题。把邻接矩阵展平喂给全连接层，参数量随节点数平方增长，还无法处理不同规模的图。按固定顺序排邻居喂给 RNN，则引入了虚假的顺序信息，同一张图换一种编号方式结果就变。

GNN 的思路是定义在邻居聚合上的运算，聚合函数要求对邻居数量不敏感、对顺序不敏感（求和、平均、最大值），这样就能在任意结构上通用。

### 3.6 GCN 的消息传递是怎么做的？

每层两步。

聚合时，每个节点收集所有邻居的特征做归一化加权求和，GCN 用对称归一化的邻接矩阵 `D^(-1/2) A D^(-1/2)`，把度信息考虑进去，避免高度节点主导聚合结果。更新时，把聚合结果与自身特征拼接或相加，过一层线性变换和激活函数，得到新的节点表示。

堆叠 K 层后，每个节点就融合了它 K 跳邻域内的信息。归一化不是可有可无的细节，不做的话高度节点的特征值会被邻居数量放大，导致数值不稳定与表示退化，这是原始 GCN 论文相比朴素传播的关键改进。

还有两个配套设计：自连接（聚合时包含自身，否则节点会丢掉自己的信息）和共享权重（同一层所有节点共用变换矩阵，这也是参数量与图规模无关的原因）。

### 3.7 GNN 的过平滑是什么？

指随着层数增加，不同节点的表示逐渐趋同，最终所有节点几乎无法区分，模型失去判别能力。

成因是消息传递本质上是图上的低通滤波，每层都在把邻居特征平均一次，多次平均后节点表示收敛到图的主分量，节点特有的信息被反复稀释。这解释了为什么实践中 GNN 通常只用 2 到 3 层，再深就退化。而 Transformer 能用几十层，因为它不做平均式传播。

缓解手段有四类：残差或跳跃连接，把浅层表示直接接到深层，保留节点自身信息；门控机制，像 GRU 一样让模型自己决定保留多少历史、吸收多少邻居信息；解耦传播与变换，先用多层 MLP 做特征变换，再做有限次传播；换聚合方式，用注意力（GAT）或成对距离感知的聚合，让重要邻居权重更大而不是简单平均。

工程上还有一招：层数不增加但扩大感受野，用图采样与多跳邻居采样代替堆层。

## 四、训练与优化

### 4.1 一次完整训练包含哪些步骤？

八步。

准备与清洗数据，做训练验证测试划分，划分必须在任何统计量计算之前完成，否则会数据泄漏。构建 Dataset 与 DataLoader，设定批大小、打乱策略、多进程加载。定义模型结构，检查参数量与输出形状是否符合预期。选择与任务匹配的损失函数。选择优化器与超参，配置学习率调度与 warmup。训练循环，对每个 batch 做前向、算损失、反向传播、优化器更新，每若干步记录损失与梯度范数。周期性在验证集上评估，保存最优 checkpoint，不能只保存最后一个，因为最后可能已过拟合。训练结束后在测试集上做一次最终评估，并固化随机种子、环境版本、数据版本。

概念澄清一下：batch 是一次参数更新用的样本数，step 或 iteration 是一次参数更新，epoch 是完整遍历训练集一次。

### 4.2 优化器怎么演进到 Adam 的？AdamW 又改了什么？

演进脉络是看每一步解决什么新问题。

SGD 用当前批次梯度更新，简单但易受噪声与病态曲率影响、收敛慢。Momentum 加入一阶动量（梯度指数移动平均），抑制震荡、加速沿一致方向前进，还能帮助冲出浅的局部极小。AdaGrad 引入二阶动量（累计梯度平方），给频繁更新的参数小步长、稀疏参数大步长，但累计量单调增长，导致学习率过早衰减到几乎为零，训练停住。RMSProp 用指数移动平均替代单调累加，解决学习率归零的问题。Adam 同时用一阶动量定方向和二阶动量定步长，再加偏差校正解决初期动量估计偏向零的问题，在绝大多数任务上收敛快、对学习率不敏感，成了默认选择。

Adam 的隐患是 L2 正则与自适应步长耦合，把 L2 加进梯度后会被二阶矩归一化，大权重受到的惩罚被削弱，泛化不如 SGD 加 momentum。AdamW 的做法是解耦权重衰减，不再把权重加进梯度，而是在更新后直接对权重乘以衰减系数，恢复了正则的作用。这也是现在大模型训练的标配。

### 4.3 混合精度为什么能加速还不掉精度？

混合精度指前向和反向用半精度计算，同时保留一份 FP32 的主权重副本用于更新。

加速来源有两层。半精度张量占用减半，显存和访存压力下降；更主要的是 Tensor Core 在低精度下的吞吐远高于 FP32。

不掉精度的关键在三点。参数更新在 FP32 里做，半精度表示范围小，梯度更新量常常小到被舍入为零，用 FP32 主副本能保住这些微小但累积起来很重要的更新。需要损失缩放，FP16 的最小正规数有限，小梯度会下溢为零，做法是先把损失放大若干倍，反向得到放大后的梯度，更新前再缩回去，缩放系数通常动态调整。敏感算子保持 FP32，比如 softmax 的归约、归一化层的统计量、损失计算这些容易出数值问题的部分。

BF16 的优势是表示范围与 FP32 相同，只牺牲尾数精度，所以通常不需要损失缩放，工程上更省心，这也是现代大模型更偏好 BF16 的原因。

### 4.4 梯度裁剪什么时候用？

梯度裁剪是限制梯度范数上界，防止个别批次产生异常大的梯度把参数一步推到坏区域，甚至造成 loss 爆炸成 NaN。

两种做法要分清：按值裁剪把每个梯度分量单独截断到 `[−c, c]`，会改变梯度的方向，一般不推荐；按范数裁剪是如果整体范数超过阈值就按比例缩放整个梯度向量，保持方向不变，这是主流做法。

适用场景有循环网络（时间步连乘容易爆炸）、序列很长或存在极端样本的训练、强化学习与 RLHF 训练（奖励尺度不稳定）、以及大模型预训练。实测中"损失尖峰导致梯度范数异常导致参数被破坏"是导致训练失败的经典链条，所以很多训练脚本会监控梯度范数并在异常时回滚 checkpoint。

边界必须强调：梯度裁剪只能解决爆炸，对梯度消失完全无效。如果被问"梯度消失怎么办"，回答裁剪是错的，应该答换激活函数、归一化、残差连接、合理初始化。

### 4.5 训练 loss 降、验证 loss 涨，怎么排查？

不能直接下结论为过拟合，要按顺序排查。

先确认是不是数据泄漏。如果验证集损失一开始就异常低，或者划分时把同源样本分到了两边（同一篇文档的不同段落分别进训练和验证），那"验证效果好"是假的，后续"上升"只是真实性能的暴露。再检查二者的预处理是否一致，验证集的归一化、增强、padding 策略是否与训练一致，不一致会导致系统性的分布差异，这是极常见且极隐蔽的 bug。然后看曲线形态，验证损失在某个点之前一直跟着训练下降、之后转折上行是典型过拟合，对策是加正则、加数据、早停、降容量；训练损失也在震荡上行则可能是学习率过大导致训练本身不稳定，而不是过拟合。再看数据量，训练集很小时过拟合几乎是必然的，此时优先补数据而不是加正则。最后检查标签质量，训练集标签有噪声时模型会去拟合噪声，表现为训练集越来越准、验证集不涨。

### 4.6 loss 变 NaN 了怎么办？

按从外向内的顺序排查。

学习率过大是最常见原因，一步更新把参数推到极端值，随后激活或损失爆掉，先降学习率或加 warmup 验证。数值运算问题也很常见，`log(0)`、`sqrt(负数)`、除零、以及 softmax 和交叉熵在极端 logits 下溢出，对策是用数值稳定的实现（log-softmax 加 NLL）、给分母加小 epsilon、对 logits 做裁剪。半精度溢出在混合精度训练里很普遍，检查损失缩放策略，或改用 BF16。输入数据异常包括某条样本含 NaN、Inf、极端值或空张量，对策是在数据处理阶段加断言，一旦发现立即定位到具体样本。梯度爆炸要加梯度范数监控与裁剪。参数初始化或权重加载问题也会导致，比如加载了不匹配的 checkpoint、或者初始化方差过大。

定位手段里最有效的是前向挂钩：逐层注册 hook 检查是否有 NaN 或 Inf 出现，第一个出问题的层就是根因所在。其次是先把 batch 缩小到 1 复现，然后二分查找是哪条样本、哪个位置触发的。从"整批炸掉"缩到"单个样本炸掉"，问题基本就清楚了。

### 4.7 早停的依据是什么？

做法是在验证集上持续监控指标，当指标连续 N 个 epoch 没有改善时停止训练，并回滚到验证指标最好的那个 checkpoint。

依据是偏差-方差权衡：随训练进行模型从欠拟合走向过拟合，验证误差呈 U 形曲线，所以存在一个最优点，早停就是在这个点附近停下来。它本质上是一种隐式正则，限制了模型在训练数据上的有效搜索时间，效果上接近 L2 正则。

实现要点有四个。监控指标不一定是损失，业务关注的指标与损失的最优点可能不同，要按最终目标选。用验证集而不是测试集来决定何时停。耐心值要足够大，否则会因训练初期的波动提前停掉；配合学习率调度时要注意学习率下降后指标常会再涨一轮，耐心值应能覆盖这个周期。保存最优 checkpoint 而非最后一个，这是最容易漏掉的一步。

### 4.8 迁移学习和微调怎么分工？冻结哪部分？

迁移学习是上位概念，把源领域学到的知识用到目标领域。微调是其中最常用的具体手段，在预训练权重基础上继续训练。

实践中按改哪些参数分三种策略。只训新加的分类头、冻结主干，适合目标数据极少（几百到几千条）且源领域与目标领域接近的情况，最不容易过拟合。部分解冻，解冻后几层或者所有层但用小学习率，数据量中等时使用，越靠后的层越偏向任务特定、越值得解冻。全参数微调，数据量大（几十万条以上）且领域差异明显时使用，效果上限最高但成本最高、最容易灾难性遗忘。

判断依据可以归纳为两个轴：数据量（小就冻结，大就全解冻）和领域差距（接近只训头，差距大解冻更多层）。

另外要警惕负迁移。如果源任务与目标任务的学习目标冲突，比如源任务优化流畅度而目标任务优化事实性，强行迁移可能比从零训练还差，这时应该降低源权重的影响或者干脆从头训。

### 4.9 灾难性遗忘怎么缓解？

指在新任务上训练后，模型在原有任务或通用能力上的表现大幅下降。成因是参数共享加无约束的梯度更新，新任务的梯度不受原有能力约束，会把承载旧知识的参数覆盖掉。

缓解手段有五类。回放或混入数据，训练新任务时按比例混入原有分布的数据，这是最有效也最常用的手段，LLM 微调时混入一定比例的通用语料就是这个思路。参数高效微调，冻结基座只训少量额外参数（LoRA、Adapter、Prefix Tuning），从结构上避免覆盖原参数。正则化约束，对"对旧任务重要的参数"施加更大的更新惩罚。降低学习率与训练步数，减少对原参数的扰动幅度。子网络或模块化隔离，为不同任务分配不同的适配模块，推理时按需组合。

评测方式很关键：必须同时报新任务收益和旧任务退化，只报前者等于隐藏了代价。实践中建议在微调前后各跑一遍通用能力评估集，把能力保持率作为放行指标之一。

## 五、框架与工程

### 5.1 动态图和静态图差在哪？

动态图（Define-by-Run）的计算图在前向执行时即时构建，每个操作直接执行并记录依赖关系。优点是调试体验极好，可以用普通 Python 断点、打印中间值、写依赖数据值的条件分支。缺点是每次前向都要重新构建图，有额外开销，单算子逐个启动也带来 Python 与内核启动开销。

静态图（Define-and-Run）先定义完整计算图再执行，图可以被整体优化，执行效率高、易于跨平台部署。缺点是调试困难，无法在图里方便地打印中间值，灵活性差，控制流需要特殊语法。

现在两边在融合。PyTorch 通过 torch.compile 和 TorchScript 把动态图捕获并编译成优化后的静态图，同时保留 Python 层的灵活性；静态图框架则加入 eager 模式。

实用结论是：开发与调试用动态图，训练与部署追求性能时启用编译。

### 5.2 autograd 是怎么工作的？

它做的事是记录前向过程中的操作，顺带构建出一张反向图。

每个张量带两个关键属性：`requires_grad` 表示是否需要梯度，`grad_fn` 指向创建它的操作节点。调用 `backward()` 时从损失出发沿 `grad_fn` 链反向遍历，用链式法则计算每个叶子张量的梯度并累积到 `.grad` 上。

三个常见坑。梯度会累积不会自动清零，必须显式调用 `optimizer.zero_grad()`，否则梯度会在多个 batch 之间累加导致训练发散；反过来这个特性也可以有意利用来实现梯度累积，小显存下模拟大 batch。验证与推理必须用 `with torch.no_grad()` 包住，否则会构建反向图，白白消耗显存和时间。注意 `model.eval()` 关闭的是 Dropout 和 BatchNorm 的随机行为，跟 no_grad 解决的是不同问题，这两件事经常被混淆。图的引用与内存也要留意，如果保留了中间张量（比如把 loss 存进列表做统计），反向图就不会释放，容易显存泄漏，需要用 `.detach()` 或 `.item()` 断开引用。

另外 in-place 操作可能破坏反向所需的中间值，PyTorch 会报错提示，遇到时改成非原地版本即可。

### 5.3 DataLoader 为什么会变成瓶颈？

因为数据准备（读文件、解码图片、做增强、组批）发生在 CPU 上，而模型计算在 GPU 上。如果数据准备比模型计算慢，GPU 就会周期性空转等数据，训练速度被数据链路拖住。典型表现是 GPU 利用率忽高忽低、呈锯齿状。

解法有四类。多进程加载让多个 CPU 进程并行准备数据，但 num_workers 不是越大越好，超过物理核心数反而因进程切换而变慢。预取让加载和计算重叠，避免"算完才取"。把预处理搬到 GPU 上做，比如把图像解码和增强放到 GPU，或改用 GPU 加速的增强库。减少数据准备成本，预先解码并缓存为二进制格式、避免每次做昂贵的解码、把可离线做的增强离线做掉。

常见误区是在 CPU 上做密集增强拖慢整条链路，尤其是逐样本的 Python 循环增强；以及数据量小时开出过多 worker 造成资源争抢。

诊断方法很直接：用 profiler 看时间线里 GPU 是否有规律的空白间隙，有就说明在等数据。

### 5.4 实验可复现要固定哪些东西？

六项。

随机种子要覆盖 Python、NumPy、框架随机源以及 CUDA 的随机性，注意多卡多进程下每个 rank 需要不同的种子偏移，否则所有进程会生成相同数据。环境版本包括 Python、框架、CUDA 和 cuDNN、以及所有依赖包的精确版本，用锁文件固化。数据版本包括数据集的快照或哈希，以及划分方式，划分本身要固定且可复现，最好把划分后的索引保存下来。代码版本要精确到 commit hash，而不是"某个分支"。配置包括所有超参、模型配置、训练步数，建议全部记录到配置文件而不是散落在代码里。硬件方面，不同 GPU 型号、不同卡数、不同并行策略会带来数值差异。

必须承认完全可复现很难。GPU 上某些算子的执行顺序不保证确定，浮点加法又不满足结合律，所以即使固定种子也可能有微小差异；追求严格一致需要开启确定性模式，会牺牲性能。实用目标是统计意义上的可复现：指标波动在可接受范围内，且结论方向一致。

落地建议是把随机种子、版本、配置统一记录下来随模型一起归档，并在实验日志里保存完整的命令行与环境信息。

### 5.5 模型保存加载有哪些坑？

先分清两种保存方式。保存整个模型对象会序列化模型结构与参数，加载时依赖原始代码定义，代码重构后就加载不了，不推荐。只保存 state_dict 只存参数字典，加载时先实例化结构再 `load_state_dict`，这是推荐做法，因为它解耦了代码与权重。

三类常见坑。参数名不匹配，加了或删了一层、或者被 `DataParallel` 包裹导致参数名多了 `module.` 前缀。解法的关键是用 `strict=False` 分析缺失与多余键，而不是直接硬加载；硬加载失败还好，如果是部分匹配成功反而会静默地只加载一部分。推理时忘记 `eval()`，Dropout 与 BatchNorm 行为不同，导致结果与训练时不一致且带随机性，这是"线上结果和离线对不上"的经典原因。优化器状态没一起保存，只存模型权重会导致恢复训练时优化器动量、二阶矩、学习率调度的状态全部丢失，loss 会出现明显的跳变，长期训练任务必须连优化器状态、当前步数、学习率调度状态一起保存。

验证做法是加载后立刻用同一批固定输入比对输出，数值一致才认为加载成功。这一步应该写进自动化流程，而不是靠肉眼看 loss 曲线。

## 六、调试与评估

### 6.1 模型不收敛，排查顺序是什么？

第一步永远是用极少样本做过拟合测试：取 5 到 20 条样本，去掉所有正则化，训练几百步，模型应该能把训练损失打到接近零。如果连这个都做不到，问题一定在代码或数据，而不是超参。这是最高效的分诊手段，能立刻把"模型不行"缩小到"实现有 bug"。

过拟合测试通过后再按顺序排查。数据管道：标签是否错位、预处理是否与预期一致、输入范围是否正常。损失函数与输出的匹配：logits 是否已经过 softmax 却又喂给了期望 logits 的损失、多分类是否用了二分类损失、mask 位置是否被错误计入损失。学习率：过大导致震荡发散、过小导致几乎不动，先用一个中等值试。优化器与参数分组：是否有参数没被加入优化器（新建的层忘记注册）、是否对不该加权重衰减的参数（norm 层与 bias）加了衰减。梯度：监控梯度范数，看是否为零（图断开或参数未参与计算）、是否溢出。初始化与归一化：初始化方差是否合理、Normalization 的维度轴是否正确，维度轴写错是极隐蔽的 bug，表现是"能训但很差"。最后检查标签与损失对齐、mask 是否正确。

经验总结是：不收敛的问题七成在数据和实现，两成在学习率，一成在其余。

### 6.2 怎么判断模型是真学到了还是记住了？

四种检验。

分布外测试，在训练分布之外的数据上评估，但"分布外"要设计得有意义（换措辞、换实体、换数值），只换无关细节测不出问题。反事实测试，改变输入中的关键变量看输出是否按逻辑改变，比如问答模型如果"把材料里的答案改成错误选项后模型仍然给出原答案"，说明它没在用材料。扰动测试，打乱语序、加无关内容、替换同义词，看输出是否稳定，不稳定说明模型依赖表面模式而非语义。模板或捷径检测，检查输入里是否存在与标签虚假相关的特征（所有正样本都来自同一个数据源），模型可能学的是这个捷径而不是真实规律，检测方式是去掉该特征后重测。

核心原则是：在同分布测试集上的高分只证明拟合得好，不证明学到了能力。这也解释了为什么大模型的评估要区分知识与推理、要做污染检测、要用对抗性测试集。

### 6.3 训练显存被谁占了？

四块。

模型参数是 `参数量 × 每参数字节数`，FP32 是 4 字节、FP16 是 2 字节，静态不变。梯度与参数同量级，通常同精度，所以按参数大小再算一份。优化器状态里 Adam 需要一阶动量和二阶动量各一份，若用 FP32 保存就是 `参数量 × 8 字节`，这往往是训练显存里最大的一块，也是大模型训练必须用 ZeRO 之类状态分片技术的原因。激活值是前向过程中各层的中间输出，需要保留到反向使用，特点是与批次大小、序列长度、层数成正比，可以远大于参数占用（Transformer 里注意力矩阵是二次的），也是梯度检查点要解决的对象，用时间换空间，只保留部分激活值、反向时重新计算其余部分。

合计下来，Adam 加 FP32 主权重加混合精度的场景，显存约为参数量的 16 到 20 倍。估算方法就是逐项相加，但必须用实测峰值校准，因为框架的显存池化、临时缓冲和碎片会让估算偏乐观。

### 6.4 让你从零训一个小模型，怎么做？

按定目标、搭基线、调优、验证四步。

先明确目标与约束：任务的输入输出是什么？目标指标是准确率还是时延？有多少数据？算力和时间预算多少？能不能用预训练权重？这里最重要的判断是，如果一个预训练模型能解决问题，就不要从零训。绝大多数工业场景的正确答案是微调。

然后搭基线：用最简单的方案跑通端到端（小模型、默认超参、单卡），拿到一个可复现的基线数字，建立评估集和记录习惯，做小样本过拟合测试验证实现正确。

再按顺序调优：优先补数据（数据是上限，性价比最高），再调数据质量与增强，再调模型容量与结构，再调学习率与调度（收益最大且最便宜），再调正则化（早停、权重衰减、Dropout），最后才考虑更复杂的技巧。这个顺序不能乱，因为前面的每一步都是后面步骤的前提。

最后验证与固化：在独立测试集上评估，做扰动与分布外测试确认模型学的是能力，记录完整实验配置，把最优配置固化成可复现的训练脚本。

三个最容易犯的错：一开始就上大模型导致实验周期太长（小步快跑比一次到位更有效）、只盯训练准确率不看验证与业务指标、没有记录配置导致最优结果无法复现。
